# v1.2.0 - 플랜 테이블 연동 및 구독 테이블 정규화

## 개요

tb_plans 테이블을 기준으로 구독 관련 테이블들의 plan_id ENUM을 plan_seq FK로 변경하여 정규화합니다.

## 변경사항

### 1. tb_subscriptions - 플랜 참조 변경

| 변경 전 | 변경 후 | 설명 |
|---------|---------|------|
| `plan_id` ENUM('free', 'minimum', 'starter', 'pro') | `plan_seq` INT UNSIGNED FK | tb_plans.seq 참조 |
| `pending_plan_id` ENUM('free', 'minimum', 'starter', 'pro') | `pending_plan_seq` INT UNSIGNED FK | tb_plans.seq 참조 |

```sql
-- 수정된 컬럼
`plan_seq` INT UNSIGNED NOT NULL COMMENT '현재 플랜 (tb_plans.seq)',
`pending_plan_seq` INT UNSIGNED NULL COMMENT '다음 결제일부터 적용될 플랜 (tb_plans.seq)',

-- 추가된 FK
CONSTRAINT `FK_SUBSCRIPTIONS_PLAN` FOREIGN KEY (`plan_seq`) REFERENCES `tb_plans` (`seq`),
CONSTRAINT `FK_SUBSCRIPTIONS_PENDING_PLAN` FOREIGN KEY (`pending_plan_seq`) REFERENCES `tb_plans` (`seq`),
```

### 2. tb_subscription_history - 플랜 참조 변경

| 변경 전 | 변경 후 | 설명 |
|---------|---------|------|
| `old_plan_id` ENUM | `old_plan_seq` INT UNSIGNED FK | tb_plans.seq 참조 |
| `new_plan_id` ENUM | `new_plan_seq` INT UNSIGNED FK | tb_plans.seq 참조 |

```sql
-- 수정된 컬럼
`old_plan_seq` INT UNSIGNED NULL COMMENT '변경 전 플랜 (tb_plans.seq)',
`new_plan_seq` INT UNSIGNED NULL COMMENT '변경 후 플랜 (tb_plans.seq)',

-- 추가된 FK
CONSTRAINT `FK_SUBHISTORY_OLD_PLAN` FOREIGN KEY (`old_plan_seq`) REFERENCES `tb_plans` (`seq`),
CONSTRAINT `FK_SUBHISTORY_NEW_PLAN` FOREIGN KEY (`new_plan_seq`) REFERENCES `tb_plans` (`seq`),
```

### 3. tb_monthly_usage - 플랜 참조 변경

| 변경 전 | 변경 후 | 설명 |
|---------|---------|------|
| `plan_id` ENUM | `plan_seq` INT UNSIGNED FK | tb_plans.seq 참조 |

```sql
-- 수정된 컬럼
`plan_seq` INT UNSIGNED NOT NULL COMMENT '해당 월의 플랜 (tb_plans.seq)',

-- 추가된 FK
CONSTRAINT `FK_USAGE_PLAN` FOREIGN KEY (`plan_seq`) REFERENCES `tb_plans` (`seq`),
```

### 4. tb_users - 플랜 참조 컬럼 제거

| 변경 전 | 변경 후 | 설명 |
|---------|---------|------|
| `current_plan_id` ENUM | **삭제** | tb_subscriptions.plan_seq로 정규화 |

**이유:**
- tb_subscriptions가 user_seq UNIQUE로 1:1 관계
- 데이터 중복 및 불일치 위험 제거
- User 조회 시 Subscription JOIN으로 플랜 정보 획득

### 5. init.sql에 추가된 테이블 DDL

- `tb_subscriptions` - 구독 정보 테이블
- `tb_subscription_history` - 구독 변경 이력 테이블
- `tb_payment_transactions` - 결제 거래 내역 테이블
- `tb_monthly_usage` - 월별 사용량 테이블
- `tb_payment_retry_schedule` - 결제 재시도 스케줄 테이블

## 근거 (Rationale)

1. **ENUM 제거**: 플랜이 추가/변경될 때 테이블 구조 변경 없이 대응 가능
2. **참조 무결성**: FK 제약조건으로 데이터 무결성 보장
3. **유연성**: 플랜 정보를 DB에서 동적으로 관리

## 영향 (Impact)

### API
- 플랜 조회 시 plan_seq로 JOIN 필요
- 구독 생성/변경 시 plan_seq 사용

### 코드 수정
- `Subscription.js`: plan_id → plan_seq
- `SubscriptionHistory.js`: old_plan_id/new_plan_id → old_plan_seq/new_plan_seq
- `MonthlyUsage.js`: plan_id → plan_seq
- `User.js`: current_plan_id → plan_seq
- `models/index.js`: Plan 관계 설정 추가

### 마이그레이션

**DDL 실행은 사용자의 책임입니다.**

기존 데이터가 있는 경우 마이그레이션 스크립트:

```sql
-- 1. 기존 plan_id를 plan_seq로 매핑
UPDATE tb_subscriptions s
JOIN tb_plans p ON UPPER(p.plan_code) = UPPER(s.plan_id)
SET s.plan_seq = p.seq;

-- 2. 기존 컬럼 삭제 (백업 후)
ALTER TABLE tb_subscriptions DROP COLUMN plan_id;
ALTER TABLE tb_subscriptions DROP COLUMN pending_plan_id;
```

## 테이블 관계도

```
tb_plans
    ├── 1:N → tb_plan_properties
    ├── 1:N → tb_subscriptions (plan_seq)
    ├── 1:N → tb_subscriptions (pending_plan_seq)
    ├── 1:N → tb_subscription_history (old_plan_seq)
    ├── 1:N → tb_subscription_history (new_plan_seq)
    ├── 1:N → tb_monthly_usage (plan_seq)
    └── 1:N → tb_users (plan_seq, 비정규화)
```
