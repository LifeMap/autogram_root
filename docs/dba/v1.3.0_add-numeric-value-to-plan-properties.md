# v1.3.0 - tb_plan_properties에 numeric_value 컬럼 추가

**버전**: v1.3.0
**날짜**: 2026-01-17
**타입**: 스키마 변경 (Schema Modification)

---

## 개요 (Overview)

tb_plan_properties 테이블에 `numeric_value` 컬럼을 추가하여 숫자 형식의 속성 값을 저장할 수 있도록 개선합니다. 기존 value_ko/value_en/value_ja는 문자열 표시용으로 유지하고, numeric_value는 비즈니스 로직에서 정량적 계산 및 제한 검증에 사용됩니다.

---

## 변경사항 (Changes)

### 1. tb_plan_properties 테이블 수정

**추가되는 컬럼:**

| 컬럼명 | 데이터 타입 | NULL 허용 | 기본값 | 설명 |
|--------|------------|----------|--------|------|
| numeric_value | DECIMAL(12,2) | YES | NULL | 숫자 값 (DM 한도, 초과 단가, 통계 보관 일수 등) |

**DDL:**
```sql
ALTER TABLE `tb_plan_properties`
  ADD COLUMN `numeric_value` DECIMAL(12,2) NULL COMMENT '숫자 값 (DM 한도, 초과 단가 등)'
  AFTER `value_ja`;
```

---

## 근거 (Rationale)

### 문제점
1. **문자열 기반 값 저장의 한계**: 현재 value_ko/value_en/value_ja는 "500건", "30일", "건당 ₩50 과금"과 같이 사람이 읽을 수 있는 형식으로 저장되어 있어 프로그래밍 로직에서 직접 활용이 어려움
2. **중복 파싱 로직 필요**: API에서 "500건"과 같은 문자열을 숫자로 파싱하는 로직이 필요하며, 국제화 처리 시 파싱 규칙이 복잡해짐
3. **비즈니스 로직 검증 어려움**: DM 발송 한도 초과 여부, 초과 요금 계산 등의 정량적 비즈니스 로직 구현 시 문자열 값으로는 직접 계산 불가

### 해결 방법
- `numeric_value` 컬럼을 추가하여 정량적 값을 별도 저장
- 문자열 표시용 컬럼(value_*)과 계산용 컬럼(numeric_value)을 분리하여 각각의 목적에 최적화
- NULL 허용으로 숫자 값이 불필요한 속성(예: "무제한", "발송 중단")에 대해서는 저장하지 않음

### 장점
1. **비즈니스 로직 단순화**: 문자열 파싱 없이 numeric_value를 직접 조회하여 제한 검증 및 요금 계산 가능
2. **타입 안정성**: DECIMAL 타입으로 정확한 금액 계산 가능 (부동소수점 오류 방지)
3. **다국어 지원 유연성**: 표시용 문자열(value_*)은 국가별로 다르게 표현 가능하지만, numeric_value는 동일한 값 유지
4. **확장성**: 향후 속성 추가 시에도 동일한 패턴 적용 가능

## 속성별 numeric_value 사용 예시

| prop_code | 설명 | numeric_value 활용 예시 |
|-----------|------|------------------------|
| DM | 월간 DM 발송 한도 | 50, 500, 1500, 10000 등 (발송 한도 검증에 사용) |
| TRIGGER | 활성 트리거 개수 | NULL (무제한이므로 숫자 값 불필요) |
| ANALYTICS | 통계 보관 기간 | 1, 30, 90 등 (일 단위, 데이터 보관 정책에 사용) |
| CTA | CTA 버튼 지원 여부 | NULL (is_support로 판단) |
| OVER_USAGE | 초과 사용 정책 | 0 (중단), 10, 30, 50 등 (건당 초과 단가, 원 단위) |

## 영향 (Impact)

### 1. API 레이어
- **영향**: PlanProperty API 응답에 `numeric_value` 필드 추가
- **작업**:
  - GET /api/plans API 응답 스키마 업데이트
  - 프론트엔드에서 비즈니스 로직 구현 시 numeric_value 활용

### 2. 비즈니스 로직
- **DM 발송 검증**: tb_plan_properties에서 prop_code='DM'인 레코드의 numeric_value를 조회하여 월간 한도 검증
- **초과 요금 계산**: prop_code='OVER_USAGE'인 레코드의 numeric_value를 조회하여 초과 건수 × 단가 계산
- **통계 보관 정책**: prop_code='ANALYTICS'인 레코드의 numeric_value를 조회하여 데이터 삭제 기준일 계산

### 3. 데이터 모델
- **영향**: PlanProperty Sequelize 모델에 numeric_value 필드 추가 필요
- **파일**: `/Volumes/Dev/workspaces/twms/sns_automation/api/src/models/PlanProperty.js`

### 4. 마이그레이션
- **기존 데이터**: 기존 레코드는 numeric_value = NULL 유지 (NULL 허용 컬럼이므로 안전)
- **신규 데이터**: seed 데이터 삽입 시 numeric_value 포함

## 업데이트된 테이블 DDL

```sql
-- ============================================
-- Table: tb_plan_properties
-- Description: 요금제 플랜 속성 테이블
-- Note: EAV 패턴으로 플랜별 기능/제한 관리
-- ============================================
CREATE TABLE `tb_plan_properties` (
  `seq` INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
  `plan_seq` INT UNSIGNED NOT NULL COMMENT '플랜 SEQ (tb_plans.seq)',
  `prop_code` ENUM('DM', 'TRIGGER', 'ANALYTICS', 'CTA', 'OVER_USAGE') NOT NULL COMMENT '속성 코드',
  `display_ko` VARCHAR(100) NOT NULL COMMENT '표시 텍스트 (한국어)',
  `display_en` VARCHAR(100) NOT NULL COMMENT '표시 텍스트 (영어)',
  `display_ja` VARCHAR(100) NOT NULL COMMENT '표시 텍스트 (일본어)',
  `value_ko` VARCHAR(45) NULL COMMENT '값 (한국어)',
  `value_en` VARCHAR(45) NULL COMMENT '값 (영어)',
  `value_ja` VARCHAR(45) NULL COMMENT '값 (일본어)',
  `numeric_value` DECIMAL(12,2) NULL COMMENT '숫자 값 (DM 한도, 초과 단가 등)',
  `is_support` TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '지원 여부 (0: 미지원, 1: 지원)',
  `sort_num` TINYINT UNSIGNED NOT NULL COMMENT '정렬 순서',
  CONSTRAINT `FK_PLANPROPERTIES_PLAN` FOREIGN KEY (`plan_seq`) REFERENCES `tb_plans` (`seq`) ON DELETE CASCADE,
  UNIQUE INDEX `UNQ_PLANPROPERTIES_01` (`plan_seq`, `prop_code`),
  INDEX `IDX_PLANPROPERTIES_01` (`plan_seq`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
COMMENT='요금제 플랜별 속성 정보를 저장하는 테이블';
```

## 검증 (Validation)

### 1. DDL 실행 후 검증
```sql
-- 컬럼 추가 확인
DESC tb_plan_properties;

-- numeric_value 컬럼 존재 여부 확인
SHOW COLUMNS FROM tb_plan_properties LIKE 'numeric_value';
```

### 2. Seed 데이터 삽입 후 검증
```sql
-- 플랜 데이터 확인
SELECT * FROM tb_plans ORDER BY sort_num;

-- 속성 데이터 확인 (numeric_value 포함)
SELECT
  p.plan_code,
  pp.prop_code,
  pp.value_ko,
  pp.numeric_value,
  pp.is_support
FROM tb_plan_properties pp
JOIN tb_plans p ON pp.plan_seq = p.seq
ORDER BY p.sort_num, pp.sort_num;
```
