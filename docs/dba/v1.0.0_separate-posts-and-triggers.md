# v1.0.0 포스트와 트리거 테이블 분리

## 개요

**버전:** v1.0.0
**작성일:** 2025-12-29
**작성자:** DBA

인스타그램 포스트 정보와 트리거 설정 정보가 혼재되어 있던 `tb_user_posts` 테이블을 목적에 맞게 분리하여, 포스트 관리와 트리거 설정을 독립적으로 처리할 수 있도록 스키마를 재설계합니다.

---

## 변경 근거

### 문제점
1. **단일 책임 원칙 위반**: `tb_user_posts` 테이블이 포스트 정보와 트리거 설정을 동시에 관리
2. **확장성 부족**: 1개 포스트에 1개 트리거만 설정 가능 (1:1 구조)
3. **데이터 중복 가능성**: 동일 포스트에 여러 트리거 설정 시 포스트 정보 중복 저장 필요
4. **Instagram API 필드 미지원**: caption, media_type, thumbnail_url 등 중요 메타데이터 미저장

### 해결 방안
- **tb_instagram_posts**: 인스타그램 포스트 원본 정보만 저장
- **tb_post_triggers**: 포스트별 트리거 설정 정보만 저장 (1:N 구조)
- **tb_trigger_execute_history**: 트리거 실행 이력 (기존 post_seq → trigger_seq 참조 변경)

---

## 변경사항

### 1. 신규 테이블: `tb_instagram_posts`

**목적:** 인스타그램 API에서 가져온 포스트 정보 저장

**주요 컬럼:**
- `seq`: 기본 키 (AUTO_INCREMENT)
- `user_seq`: 포스트 소유자 (tb_users.seq 참조)
- `media_id`: Instagram Media ID (고유 식별자)
- `caption`: 포스트 캡션
- `media_type`: 미디어 타입 (IMAGE, VIDEO, CAROUSEL_ALBUM)
- `media_url`: 미디어 URL
- `permalink`: Instagram 포스트 permalink
- `timestamp`: Instagram 게시 시간
- `thumbnail_url`: 썸네일 URL (비디오용)
- `created_at`: 데이터베이스 저장 시간
- `last_synced_at`: 마지막 동기화 시간

**제약 조건:**
- `FK_INSTAPOSTS_USER`: user_seq → tb_users.seq (CASCADE DELETE)
- `UNQ_INSTAPOSTS_01`: (user_seq, media_id) UNIQUE

---

### 2. 신규 테이블: `tb_post_triggers`

**목적:** 인스타그램 포스트별 트리거 설정 정보 저장 (1:N 관계)

**주요 컬럼:**
- `seq`: 기본 키 (AUTO_INCREMENT)
- `post_seq`: 트리거를 설정할 포스트 (tb_instagram_posts.seq 참조)
- `user_seq`: 트리거 소유자 (tb_users.seq 참조)
- `trigger_word`: DM을 보낼 트리거 단어
- `dm_message`: 자동 발송 DM 메시지
- `trigger_follow`: 팔로워만 응답 여부 (0/1)
- `reply_comment`: 댓글 답글 여부 (0/1) **[신규]**
- `reply_comment_text`: 댓글 답글 내용 **[신규]**
- `status`: 트리거 상태 (ACTIVATED, SUSPENDED)
- `created_at`, `last_updated_at`, `suspended_at`: 시간 정보

**제약 조건:**
- `FK_POSTTRIGGERS_POST`: post_seq → tb_instagram_posts.seq (CASCADE DELETE)
- `FK_POSTTRIGGERS_USER`: user_seq → tb_users.seq (CASCADE DELETE)
- `UNQ_POSTTRIGGERS_01`: (post_seq, trigger_word, status) UNIQUE
- `IDX_POSTTRIGGERS_01`: (user_seq, status) INDEX
- `IDX_POSTTRIGGERS_02`: (post_seq, status) INDEX

---

### 3. 수정 테이블: `tb_trigger_execute_history`

**변경 내용:**
- 기존 `post_seq` → `trigger_seq`로 컬럼명 변경
- 참조 테이블 변경: tb_user_posts.seq → tb_post_triggers.seq
- 인덱스 추가:
  - `IDX_TRIGGERHISTORY_01`: (trigger_seq, status)
  - `IDX_TRIGGERHISTORY_02`: (user_id, created_at)

---

### 4. 삭제 테이블: `tb_user_posts`

**삭제 근거:**
- 포스트 정보는 `tb_instagram_posts`로 이관
- 트리거 정보는 `tb_post_triggers`로 이관
- 역할이 명확히 분리되어 더 이상 필요 없음

## DDL 문

### 1. tb_instagram_posts 생성

```sql
CREATE TABLE `tb_instagram_posts` (
  `seq` INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
  `user_seq` INT UNSIGNED NOT NULL COMMENT '포스트 소유자 (tb_users.seq)',
  `media_id` VARCHAR(500) NOT NULL COMMENT 'Instagram Media ID',
  `caption` TEXT NULL COMMENT '포스트 캡션',
  `media_type` ENUM('IMAGE', 'VIDEO', 'CAROUSEL_ALBUM') NOT NULL COMMENT '미디어 타입',
  `media_url` TEXT NOT NULL COMMENT '미디어 URL',
  `permalink` TEXT NOT NULL COMMENT 'Instagram 포스트 permalink',
  `timestamp` DATETIME(6) NULL COMMENT 'Instagram에서 게시된 시간',
  `thumbnail_url` TEXT NULL COMMENT '썸네일 URL (비디오용)',
  `created_at` DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6) COMMENT '데이터베이스 저장 시간',
  `last_synced_at` DATETIME(6) NULL COMMENT '마지막 동기화 시간',
  CONSTRAINT `FK_INSTAPOSTS_USER` FOREIGN KEY (`user_seq`) REFERENCES `tb_users` (`seq`) ON DELETE CASCADE,
  UNIQUE INDEX `UNQ_INSTAPOSTS_01` (`user_seq`, `media_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
COMMENT='인스타그램에서 가져온 포스트 정보를 저장하는 테이블';
```

### 2. tb_post_triggers 생성

```sql
CREATE TABLE `tb_post_triggers` (
  `seq` INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
  `post_seq` INT UNSIGNED NOT NULL COMMENT '트리거를 설정할 포스트 (tb_instagram_posts.seq)',
  `user_seq` INT UNSIGNED NOT NULL COMMENT '트리거 소유자 (tb_users.seq)',
  `trigger_word` VARCHAR(30) NOT NULL COMMENT 'DM을 보낼 트리거 단어',
  `dm_message` VARCHAR(1000) NOT NULL COMMENT '자동으로 발송할 DM 메시지',
  `trigger_follow` TINYINT NOT NULL DEFAULT 0 COMMENT '팔로워만 응답 (0: 아니오, 1: 예)',
  `reply_comment` TINYINT NOT NULL DEFAULT 0 COMMENT '댓글 답글 여부 (0: 아니오, 1: 예)',
  `reply_comment_text` VARCHAR(1000) NULL COMMENT '댓글 답글 내용',
  `status` ENUM('ACTIVATED', 'SUSPENDED') NOT NULL DEFAULT 'ACTIVATED' COMMENT '트리거 상태',
  `created_at` DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
  `last_updated_at` DATETIME(6) NULL ON UPDATE CURRENT_TIMESTAMP(6),
  `suspended_at` DATETIME(6) NULL COMMENT '트리거 중단 시간',
  CONSTRAINT `FK_POSTTRIGGERS_POST` FOREIGN KEY (`post_seq`) REFERENCES `tb_instagram_posts` (`seq`) ON DELETE CASCADE,
  CONSTRAINT `FK_POSTTRIGGERS_USER` FOREIGN KEY (`user_seq`) REFERENCES `tb_users` (`seq`) ON DELETE CASCADE,
  UNIQUE INDEX `UNQ_POSTTRIGGERS_01` (`post_seq`, `trigger_word`, `status`),
  INDEX `IDX_POSTTRIGGERS_01` (`user_seq`, `status`),
  INDEX `IDX_POSTTRIGGERS_02` (`post_seq`, `status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
COMMENT='인스타그램 포스트에 설정된 트리거 정보를 저장하는 테이블';
```

### 3. tb_trigger_execute_history 수정

```sql
-- 기존 외래 키 삭제
ALTER TABLE `tb_trigger_execute_history`
  DROP FOREIGN KEY IF EXISTS `tb_trigger_execute_history_ibfk_1`;

-- 컬럼명 변경
ALTER TABLE `tb_trigger_execute_history`
  CHANGE COLUMN `post_seq` `trigger_seq` INT UNSIGNED NOT NULL COMMENT '트리거 SEQ (tb_post_triggers.seq)';

-- 새 외래 키 추가
ALTER TABLE `tb_trigger_execute_history`
  ADD CONSTRAINT `FK_TRIGGERHISTORY_TRIGGER`
  FOREIGN KEY (`trigger_seq`) REFERENCES `tb_post_triggers` (`seq`) ON DELETE CASCADE;

-- 인덱스 추가
ALTER TABLE `tb_trigger_execute_history`
  ADD INDEX `IDX_TRIGGERHISTORY_01` (`trigger_seq`, `status`),
  ADD INDEX `IDX_TRIGGERHISTORY_02` (`user_id`, `created_at`);
```

### 4. 데이터 마이그레이션 (기존 데이터가 있는 경우)

```sql
-- Step 1: 포스트 정보를 tb_instagram_posts로 이관
INSERT INTO `tb_instagram_posts`
  (`user_seq`, `media_id`, `media_url`, `permalink`, `created_at`)
SELECT
  `user_seq`,
  `post_id`,
  `post_url`,
  `post_url`, -- permalink로 임시 사용
  `created_at`
FROM `tb_user_posts`
WHERE NOT EXISTS (
  SELECT 1 FROM `tb_instagram_posts` ip
  WHERE ip.user_seq = `tb_user_posts`.user_seq
  AND ip.media_id = `tb_user_posts`.post_id
);

-- Step 2: 트리거 정보를 tb_post_triggers로 이관
INSERT INTO `tb_post_triggers`
  (`post_seq`, `user_seq`, `trigger_word`, `dm_message`, `trigger_follow`,
   `reply_comment`, `status`, `created_at`, `last_updated_at`, `suspended_at`)
SELECT
  ip.seq,
  up.user_seq,
  up.trigger_word,
  up.dm_message,
  up.trigger_follow,
  0, -- reply_comment 기본값
  up.status,
  up.created_at,
  up.last_updated_at,
  up.suspended_at
FROM `tb_user_posts` up
INNER JOIN `tb_instagram_posts` ip
  ON up.user_seq = ip.user_seq
  AND up.post_id = ip.media_id;

-- Step 3: tb_trigger_execute_history의 post_seq를 trigger_seq로 업데이트
UPDATE `tb_trigger_execute_history` teh
INNER JOIN `tb_user_posts` up ON teh.post_seq = up.seq
INNER JOIN `tb_instagram_posts` ip ON up.user_seq = ip.user_seq AND up.post_id = ip.media_id
INNER JOIN `tb_post_triggers` pt ON pt.post_seq = ip.seq AND pt.trigger_word = up.trigger_word
SET teh.post_seq = pt.seq;

-- Step 4: 기존 tb_user_posts 테이블 삭제
DROP TABLE `tb_user_posts`;
```

## 영향 분석

### API 영향
1. **포스트 저장 API**: 신규 생성 필요 (`POST /api/v1/instagram/posts`)
2. **트리거 설정 API**: 기존 API 수정 필요 (`post_seq` 참조 변경)
3. **트리거 목록 조회 API**: JOIN 쿼리 변경 필요 (포스트 정보 포함)

### 애플리케이션 코드 영향
1. **Sequelize 모델**: 3개 모델 생성/수정 필요
   - `InstagramPost.js` (신규)
   - `PostTrigger.js` (신규)
   - `TriggerExecuteHistory.js` (수정)
2. **컨트롤러/서비스 로직**: 트리거 설정 시 포스트 존재 여부 검증 추가

### 성능 영향
- **긍정적**: 포스트와 트리거 독립 조회 시 스캔 범위 감소
- **긍정적**: 인덱스 최적화로 트리거 검색 성능 향상
- **주의**: JOIN 쿼리 증가로 복합 조회 시 주의 필요 (적절한 인덱스로 완화)

## 관련 테이블

- `tb_users`: 사용자 정보
- `tb_instagram_posts`: 인스타그램 포스트 정보 **[신규]**
- `tb_post_triggers`: 포스트별 트리거 설정 **[신규]**
- `tb_trigger_execute_history`: 트리거 실행 이력 **[수정]**

---

## 테이블 관계도

```
tb_users (사용자)
  ├─→ 1:N → tb_instagram_posts (인스타그램 포스트)
  │              ├─→ 1:N → tb_post_triggers (포스트별 트리거)
  │              │              ├─→ 1:N → tb_trigger_execute_history (실행 이력)
  │              │              └─→ FK: user_seq → tb_users.seq
  │              └─→ FK: user_seq → tb_users.seq
  └─→ 1:N → tb_post_triggers (트리거 소유자 관계)
```

## 참고사항

### Instagram API 필드 매핑
| Instagram API 필드 | 테이블 컬럼 | 타입 | 비고 |
|------------------|----------|------|------|
| id | media_id | VARCHAR(500) | 고유 식별자 |
| caption | caption | TEXT | 포스트 내용 |
| media_type | media_type | ENUM | IMAGE/VIDEO/CAROUSEL_ALBUM |
| media_url | media_url | TEXT | 미디어 원본 URL |
| permalink | permalink | TEXT | 포스트 공유 링크 |
| timestamp | timestamp | DATETIME(6) | 게시 시간 (ISO 8601) |
| thumbnail_url | thumbnail_url | TEXT | 비디오 썸네일 (선택) |

### 트리거 설정 비즈니스 로직
- 1개 포스트에 여러 트리거 단어 설정 가능
- 동일 트리거 단어는 ACTIVATED 상태에서 1개만 존재
- SUSPENDED 상태로 변경 시 동일 트리거 단어 재생성 가능
- 포스트 삭제 시 관련 트리거 및 실행 이력 모두 삭제 (CASCADE)
