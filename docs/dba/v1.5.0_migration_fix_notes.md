## 🔧 수정 내용 요약

### 1. 마이그레이션 스크립트 수정 (`v1.5.0_multi-instagram-accounts.sql`)

#### **Step 11 분리 및 컬럼명 수정**
- **기존 문제**:
  - 잘못된 컬럼명 사용: `year_month` → 올바른 컬럼명은 `usage_month`
  - 잘못된 인덱스명 참조: `UNQ_MONTHLYUSAGE_01` → 실제로는 `UNQ_USAGE_USER_MONTH`
  - DROP과 ADD를 동시에 실행하여 에러 발생 가능성

- **수정 사항**:
  ```sql
  -- Step 11: tb_monthly_usage 외래 키 및 인덱스 추가
  ALTER TABLE `tb_monthly_usage`
    ADD CONSTRAINT `FK_MONTHLYUSAGE_OAUTH`
      FOREIGN KEY (`oauth_seq`) REFERENCES `tb_user_oauth` (`seq`) ON DELETE CASCADE,
    ADD INDEX `IDX_MONTHLYUSAGE_02` (`oauth_seq`, `usage_month`);

  -- Step 12: tb_monthly_usage UNIQUE 제약 재설정
  ALTER TABLE `tb_monthly_usage`
    DROP INDEX `UNQ_USAGE_USER_MONTH`,
    ADD UNIQUE INDEX `UNQ_USAGE_USER_MONTH` (`user_seq`, `oauth_seq`, `usage_month`);
  ```

#### **Step 번호 재조정**
- Step 11 → Step 11 + Step 12로 분리
- 기존 Step 12 → Step 13
- 기존 Step 13 → Step 14

## 📊 현재 tb_monthly_usage 테이블 구조 확인

```sql
CREATE TABLE sns_automation.tb_monthly_usage
(
    seq                      INT UNSIGNED AUTO_INCREMENT COMMENT '사용량 레코드 ID'
        PRIMARY KEY,
    user_seq                 INT UNSIGNED                               NOT NULL COMMENT '사용자 (tb_users.seq)',
    oauth_seq                INT UNSIGNED                               NULL COMMENT '계정별 사용량 추적 (NULL = 기존 통합 데이터)',
    plan_seq                 INT UNSIGNED                               NOT NULL,
    plan_id                  ENUM ('free', 'minimum', 'starter', 'pro') NOT NULL COMMENT '해당 월의 플랜 ID',
    usage_month              CHAR(7)                                    NOT NULL,  -- ⭐ 핵심: usage_month
    dm_sent_count            INT UNSIGNED DEFAULT '0'                   NOT NULL COMMENT '실제 발송 건수',
    created_at               DATETIME(6)  DEFAULT CURRENT_TIMESTAMP(6)  NOT NULL COMMENT '레코드 생성 시간',
    updated_at               DATETIME(6)  DEFAULT CURRENT_TIMESTAMP(6)  NOT NULL,
    warning_email_sent       TINYINT      DEFAULT 0                     NOT NULL COMMENT '90% 경고 이메일 발송 여부',
    quota_reached_email_sent TINYINT      DEFAULT 0                     NOT NULL COMMENT '100% 차단 이메일 발송 여부',

    CONSTRAINT UNQ_USAGE_USER_MONTH                                      -- ⭐ 핵심: 정확한 인덱스명
        UNIQUE (user_seq, usage_month) COMMENT '사용자별 월별 단일 레코드',
    CONSTRAINT FK_USAGE_PLAN
        FOREIGN KEY (plan_seq) REFERENCES sns_automation.tb_plans (seq),
    CONSTRAINT FK_USAGE_USER
        FOREIGN KEY (user_seq) REFERENCES sns_automation.tb_users (seq)
            ON DELETE CASCADE
);
```

## 📌 주의사항

1. **DDL 실행 책임**:
   - 모든 DDL 스크립트는 사용자가 직접 검토 후 실행해야 함
   - 프로덕션 환경에서는 반드시 개발 환경에서 테스트 후 실행

2. **데이터 마이그레이션**:
   - Step 9, 10이 이미 실행되어 `oauth_seq` 컬럼이 존재하는 경우, 해당 Step 건너뛰기
   - Step 11, 12만 순차적으로 실행

3. **외래 키 제약**:
   - `FK_MONTHLYUSAGE_OAUTH`가 이미 존재하면 Step 11에서 에러 발생 가능
   - 중복 실행 방지를 위해 실행 전 제약조건 확인:
     ```sql
     SHOW CREATE TABLE tb_monthly_usage;
     ```

4. **UNIQUE 인덱스 충돌**:
   - Step 12에서 기존 `UNQ_USAGE_USER_MONTH` 삭제 후 재생성
   - 삭제 전 인덱스 존재 여부 확인 필수
